# 性能优化与模型灵活性

**日期：** 2026-09-06
**问题：** 50-100 栋建筑会不会资源占用过高？生成的模型如何灵活运用？

---

## 一、性能分析：50-100 栋建筑到底多大？

### 1.1 真实数据估算

| 元素 | 数量 | 单个面数 | 总面数 |
|------|------|---------|--------|
| Haussmann 建筑（简化盒子） | 80 栋 | 12-24 面 | 960-1,920 |
| 建筑细节（窗户、阳台） | 80 栋 | 50-100 面 | 4,000-8,000 |
| 街道路面 | 10 块 | 4-8 面 | 40-80 |
| 行道树 | 30 棵 | 200-400 面 | 6,000-12,000 |
| 路灯 | 20 个 | 50-100 面 | 1,000-2,000 |
| 长椅 | 15 个 | 50-100 面 | 750-1,500 |
| **总计** | | | **12,750-25,500** |

**结论：** 总面数在 13,000-25,000 之间。这个规模**远低于**性能瓶颈。

### 1.2 对比参考

| 场景 | 典型面数 | Web 端 fps |
|------|---------|-----------|
| 简单场景（<10k 面） | 5,000 | 60+ fps |
| **语宙 V1（13k-25k 面）** | **20,000** | **40-60 fps** |
| 中等场景（50k 面） | 50,000 | 30-40 fps |
| 复杂场景（100k+ 面） | 100,000 | 20-30 fps |

**结论：** 13k-25k 面在 Web 端完全可承受，甚至不需要 LOD。

## 二、优化策略（不砍区域、不改布局）

即使当前规模不需要优化，提前规划好优化策略是正确的。

### 2.1 建筑网格简化

```
原始 OSM 建筑轮廓（可能有 20-50 个顶点）
        │
        ▼
    简化为矩形（4 个顶点）
        │
        ▼
    拉伸为盒子（12 个面）
```

**具体做法：**
- 每栋建筑用 **一个盒子** 表示（12 个面）
- 不需要精确的轮廓形状——巴黎建筑大多是矩形
- 如果建筑形状复杂（L形、U形），拆成 2-3 个盒子

**效果：** 80 栋建筑 × 12 面 = 960 面（比原始数据减少 90%+）

### 2.2 细节层次（LOD）策略

| 距离 | LOD | 建筑表现 | 面数/栋 |
|------|-----|---------|--------|
| 0-20m（近处） | LOD0 | 完整盒子 + 窗户纹理 | 12-24 面 |
| 20-50m（中距离） | LOD1 | 简化盒子 + 纯色 | 12 面 |
| 50m+（远处） | LOD2 | 极简盒子 | 6 面 |

**Godot 实现：** 用 `LOD` 节点或手动切换 MeshInstance3D 的 mesh。

### 2.3 纹理优化

| 策略 | 说明 | 效果 |
|------|------|------|
| **纹理图集** | 把所有建筑纹理合并成一张大图 | 减少 Draw Call |
| **纯色材质** | 大部分建筑用纯色（不需要纹理） | 零纹理开销 |
| **重复使用** | 所有 Haussmann 建筑共享同一套材质 | 内存节省 |

**推荐方案：** V1 用纯色材质（奶白外墙+灰屋顶），不需要纹理。后续再加细节。

### 2.4 实例化渲染（Instancing）

```
相同的建筑类型 → 共享同一个 Mesh → GPU 只加载一次
```

**具体做法：**
- 所有矩形建筑共享一个 "盒子" Mesh
- 只是缩放和位置不同
- Godot 自动处理实例化

**效果：** 80 栋建筑 = 1 个 Mesh 实例 × 80 个 Transform

### 2.5 视锥剔除（Frustum Culling）

```
玩家看向左边 → 右边的建筑不渲染
玩家看向前面 → 身后的建筑不渲染
```

**Godot 自动支持：** Three.js / Godot 都默认开启视锥剔除。不需要额外代码。

### 2.6 遮挡剔除（Occlusion Culling）

```
玩家在街道上 → 街道两侧的建筑互相遮挡 → 被遮挡的不渲染
```

**Godot 4 支持：** 在 Project Settings 中开启 `rendering/occlusion_culling/use_occlusion_culling`。

### 2.7 按需加载（Streaming）

```
玩家在 A 街区 → 只加载 A 街区的建筑
玩家走到 B 街区 → 卸载 A，加载 B
```

**V1 不需要：** 500m × 500m 范围内所有建筑可以一次性加载。
**V2 考虑：** 如果扩展到整个巴黎，需要分块加载。

## 三、优化后的性能预算

| 指标 | 优化前 | 优化后 | 说明 |
|------|--------|--------|------|
| 总面数 | 25,000 | 10,000-15,000 | 盒子简化 + LOD |
| Draw Call | 80+ | 5-10 | 实例化 + 纹理图集 |
| 纹理内存 | 高 | 低/零 | 纯色材质 |
| 加载时间 | 中 | 低 | 包体更小 |
| 帧率 | 40 fps | 55-60 fps | 优化后接近满帧 |

## 四、生成模型的灵活性

### 4.1 生成的是什么？

```
OSM 数据 → Blender 生成 → glTF 文件 → Godot 场景节点
```

生成的是**标准的3D网格**，跟手动建模的模型没有任何区别。可以像任何其他3D资产一样使用。

### 4.2 可以做什么？

| 操作 | 说明 | 难度 |
|------|------|------|
| **移动/旋转/缩放** | 像搭积木一样摆放 | 低 |
| **换材质** | 重新上色、换纹理 | 低 |
| **添加细节** | 加窗户、阳台、门 | 中 |
| **删除/替换** | 删掉某栋楼，换成手动建模的 | 低 |
| **合并** | 多栋楼合并成一个节点 | 低 |
| **拆分** | 一栋楼拆成多个部分 | 中 |
| **动画** | 开门、亮灯、招牌旋转 | 中 |
| **碰撞体** | 添加简化碰撞体 | 低 |
| **对话区域** | 标记可进入的建筑 | 低 |

### 4.3 灵活运用示例

**示例 1：标记咖啡馆**
```
从 80 栋建筑中选 1 栋 → 标记为"咖啡馆" → 
添加内部场景（手动建模）→ 设置 NPC 点位
```

**示例 2：自定义街区**
```
生成整个玛黑区 → 只保留 1 条街道的建筑 → 
删除其余 → 聚焦小范围
```

**示例 3：混合生成+手建**
```
生成的建筑作为"远景" → 手动建模的建筑作为"近景" →
近处精细、远处简化
```

**示例 4：程序化细节**
```
生成的盒子建筑 → 程序化添加窗户（在 Shader 中）→
不需要建模，Shader 自动生成窗户图案
```

### 4.4 程序化细节（Shader 方案）

不需要为每栋建筑建模窗户，用 Shader 自动生成：

```glsl
// 伪代码：在 Shader 中生成窗户图案
vec2 uv = UV * vec2(4.0, 6.0);  // 4列窗户 × 6层
float window = step(0.3, fract(uv.x)) * step(0.3, fract(uv.y));
vec3 color = mix(wallColor, windowColor, window);
```

**效果：** 所有建筑共享一个 Shader，自动生成窗户、阳台图案。零额外建模。

## 五、最终推荐方案

### 5.1 生成策略

```
1. OSM 数据 → Blender GIS 导入
2. 每栋建筑简化为盒子（12面）
3. 用 Haussmann 纯色材质（不需要纹理）
4. 程序化 Shader 添加窗户细节
5. 导出 glTF → Godot
```

### 5.2 优化策略（V1 需要的）

| 策略 | 是否需要 | 说明 |
|------|---------|------|
| 建筑盒子简化 | ✅ 必须 | 从 50 面/栋降到 12 面/栋 |
| 纯色材质 | ✅ 推荐 | 零纹理开销 |
| 视锥剔除 | ✅ 自动 | Godot 默认开启 |
| LOD | ⚠️ V1 不需要 | 场景小，不需要 |
| 实例化 | ⚠️ V1 不需要 | 面数足够低 |
| 遮挡剔除 | ⚠️ 可选 | 开启后更流畅 |
| 按需加载 | ❌ V1 不需要 | 场景小，一次加载 |

### 5.3 灵活性保证

- 生成的是标准 glTF → 可以自由修改
- 每栋建筑是独立节点 → 可以单独编辑
- 可以混合生成+手建 → 近景精细、远景简化
- 可以用 Shader 添加细节 → 不需要额外建模

## 六、结论

| 问题 | 答案 |
|------|------|
| 50-100 栋建筑会不会卡？ | **不会。** 简化后总面数 < 15,000，Web 端 55+ fps |
| 不砍区域怎么优化？ | **盒子简化 + 纯色材质 + 视锥剔除**，不需要砍 |
| 生成的模型能改吗？ | **能。** 标准 glTF，跟手建模型一样灵活 |
| 能加细节吗？ | **能。** Shader 程序化生成窗户，不需要建模 |
