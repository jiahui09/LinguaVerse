# 语宙（LinguaVerse）V1 开发计划

**版本：** 1.0
**日期：** 2026-09-06
**范围：** V1 垂直切片——巴黎咖啡馆场景虚拟体验
**引擎：** Godot 4.7.2 + Blender 4.2.8

---

## 〇、V1 体验闭环

```
打开网页 → 巴黎街头 → WASD 探索 → 走进咖啡馆 →
服务员招呼 → 键盘对话 → NPC 自由回应 → 咖啡端来 →
走出咖啡馆 → 天色变化
```

**V1 验证的核心假设：**
1. POV + 自由探索是否比"场景选择"更能引发探索欲？
2. NPC 的自由对话（LLM 驱动）是否比预设脚本更自然？
3. 昼夜循环是否让世界感觉"活"？
4. Web 端 3D 场景是否能达到可接受帧率？

### Phase 2：3D 世界场景（M1，3-5 天）

> 目标：搭建可行走的巴黎街景

#### 2.1 资产制作（Blender）

| # | 资产 | 面数预算 | 来源策略 |
|---|------|---------|---------|
| 2.1.1 | 法式建筑外立面 ×3-5 | 2,000-5,000/栋 | Quaternius CC0 + 调整 |
| 2.1.2 | 石板路面 | 100-200 | 自建（平面 + 纹理） |
| 2.1.3 | 行道树 ×2-3 | 500-1,000/棵 | Quaternius CC0 |
| 2.1.4 | 路灯 ×2-3 | 200-500/个 | Quaternius CC0 |
| 2.1.5 | 长椅 ×1-2 | 200-400/个 | Quaternius CC0 |
| 2.1.6 | 咖啡馆外壳 | 3,000-5,000 | 自建或 Quaternius 改 |
| 2.1.7 | 咖啡馆内部家具 | 2,000-4,000 | Quaternius 家具包 |
| 2.1.8 | 施工围栏（边界） | 200-500 | 自建 |

**资产获取优先级：**
1. 先检查 [Quaternius](https://quaternius.com/) CC0 包能否覆盖需求
2. 不够的部分用 Blender 简单建模
3. 纹理用纯色/简单渐变（低多边形风格）

#### 2.2 场景搭建（Godot 编辑器）

| # | 任务 | 说明 |
|---|------|------|
| 2.2.1 | 搭建 100m 街道布局 | 建筑排列、路面铺设、道具摆放 |
| 2.2.2 | 搭建咖啡馆室内 | 柜台区 + 座位区 + 可行走空间 |
| 2.2.3 | 放置 NPC 点位 | 服务员柜台、行人路径、老人长椅 |
| 2.2.4 | 基础光照 | DirectionalLight（昼夜用）+ 环境光 |
| 2.2.5 | 边界处理 | 街道尽头施工围栏 |

**Phase 2 交付：** 可以在巴黎街景中自由行走的场景（无 NPC、无对话）。

### Phase 3：玩家系统（M2，1-2 天）

> 目标：完善第一人称交互体验

| # | 任务 | 复杂度 | 说明 |
|---|------|--------|------|
| 3.1 | 第一人称控制器打磨 | 低 | 调试移动速度、鼠标灵敏度、碰撞体 |
| 3.2 | 视线晃动 | 低 | 走路时轻微上下晃动（sin 波） |
| 3.3 | 交互检测（射线） | 中 | 从 Camera3D 发射射线，检测可交互物体 |
| 3.4 | 交互提示 UI | 低 | 视线中央出现"按 E 交互"提示（DOM 叠加） |
| 3.5 | 与对话系统对接 | 中 | 按 E 时触发 dialog_manager.start_dialog_with(npc) |

**技术要点：**
- 射线检测用 `PhysicsDirectSpaceState3D.intersect_ray()`
- 可交互物体需设置 `collision_layer` 和自定义 `interactable` 组
- 交互提示用 JavaScriptBridge DOM 叠加

**Phase 3 交付：** 可以在场景中移动，靠近 NPC 时出现交互提示，按 E 触发对话。

---

### Phase 4：NPC 系统（M3，3-5 天）

> 目标：3 个有行为的 NPC

#### 4.1 NPC 资产（Blender）

| # | 资产 | 面数预算 | 说明 |
|---|------|---------|------|
| 4.1.1 | 服务员模型 | 1,000-3,000 | 低多边形人形，围裙 |
| 4.1.2 | 行人模型 | 1,000-3,000 | 低多边形人形，休闲装 |
| 4.1.3 | 老人模型 | 1,000-3,000 | 低多边形人形，朴素装 |
| 4.1.4 | NPC 动画 | - | idle（站立）、walk（走路） |

**资产策略：** 可以用 Quaternius 的角色包作为基础，或用 Mixamo 获取免费动画。

#### 4.2 NPC 脚本（GDScript）

| # | 任务 | 说明 |
|---|------|------|
| 4.2.1 | NPC 状态机完善 | idle → walk → interact → talking 状态转换 |
| 4.2.2 | 服务员行为 | 柜台后 idle → 玩家靠近 → 招呼 → 等待对话 |
| 4.2.3 | 行人行为 | 沿预设路径走动 → 到达终点 → 返回 |
| 4.2.4 | 老人行为 | 长椅上 idle → 玩家靠近 → 闲聊 |
| 4.2.5 | NPC 名牌 UI | 头顶显示名字（3D Label 或 DOM 叠加） |

**NPC 对话 Prompt 模板：**
```
你是 {名字}，一个巴黎 {职业}。
你的性格是 {性格}。
你现在在 {位置}，当前时间是 {时间}。
你会说法语，但不会英语。
玩家是一个刚搬到巴黎的新居民，法语不太好。
说话要求：自然、口语化、简短。
```

**Phase 4 交付：** 3 个 NPC 在场景中有行为，靠近会打招呼。

---

### Phase 5：对话系统（M4，3-5 天）

> 目标：完整的对话体验闭环

#### 5.1 前端（Godot 侧）

| # | 任务 | 说明 |
|---|------|------|
| 5.1.1 | 对话触发逻辑 | 靠近 NPC → 自动招呼 → 等待玩家输入 |
| 5.1.2 | DOM 叠加 UI | JavaScriptBridge 创建台词气泡 + 输入框 |
| 5.1.3 | NPC 思考动作 | 等待 AI 响应时 NPC 做思考动作（点头/皱眉） |
| 5.1.4 | 对话结束逻辑 | 玩家走开 / NPC 说完 → 自然结束，无"退出按钮" |
| 5.1.5 | 对话记忆 | NPC 记得刚才聊过（短期记忆，刷新重置） |

#### 5.2 后端（Node.js + Fastify）

| # | 任务 | 说明 |
|---|------|------|
| 5.2.1 | Fastify 服务搭建 | 基础 HTTP 服务器 + CORS |
| 5.2.2 | LLM 适配器层 | 统一接口，支持 Ollama / DeepSeek / OpenAI |
| 5.2.3 | Prompt 组装器 | NPC 身份 + 世界状态 + 对话历史 → Prompt |
| 5.2.4 | 对话 API | POST /api/dialog（请求-响应） |
| 5.2.5 | SSE 流式 API | POST /api/dialog/stream（逐字生成） |
| 5.2.6 | 世界状态 API | GET /api/world-state（时间、NPC 状态） |

**API 设计：**

```
POST /api/dialog
Request:  { player_input, npc_info, conversation_history, world_state }
Response: { text, npc_name }

POST /api/dialog/stream
Request:  { player_input, npc_info, conversation_history, world_state }
Response: SSE 流，每个 chunk: data: {"text": "词", "done": false}

GET /api/world-state
Response: { time_of_day, npc_states }
```

**Phase 5 交付：** 完整的对话体验——靠近 NPC → 打招呼 → 键盘输入 → AI 自由回复 → 气泡显示。

## 五、技术约束

| 约束 | 说明 | 应对 |
|------|------|------|
| Web 性能 | 桌面浏览器 30+ fps | 场景 < 30,000 面，Compatibility 渲染器 |
| 包体大小 | 首次加载可接受 | Godot 运行时 ~15MB + 资产 ~5MB |
| LLM 延迟 | NPC 回复 < 3 秒 | 思考动作 + 流式响应 |
| 浏览器兼容 | 现代浏览器 | Chrome / Firefox / Edge，WebGL 2.0 |
| 单线程 | Godot 4.3+ 默认 | 不需要 SharedArrayBuffer 头 |

## 六、风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| Godot Web 导出性能差 | 中 | 高 | 场景足够小；降级为低画质 |
| JavaScriptBridge 不稳定 | 低 | 高 | Godot 4.x 已稳定，官方文档确认 |
| 3D 资产制作耗时 | 高 | 中 | 优先用 CC0 资产，不追求完美 |
| LLM 响应太慢 | 中 | 中 | 思考动作掩盖延迟；流式响应 |
| 团队不熟悉 GDScript | 中 | 中 | GDScript 语法简单，1-2 天上手 |

## 八、完成标准

### 玩家体验闭环
```
打开网页 → 进入巴黎街头 → WASD 移动探索 → 走进咖啡馆 →
服务员招呼 → 键盘输入对话 → NPC 自由回应 → 咖啡端来 →
```

- 桌面浏览器稳定 30+ fps
- NPC 对话响应延迟 < 3 秒
