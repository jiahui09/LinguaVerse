# 性能优化 — 设计与实施

> 立项：`/godot-master` 任务 —— "对本项目进行彻底的优化设计，只要能保质保量实现核心目标与效果即可"。
> 方法：先审计、再设计、只做能被度量证明的优化，最后用既有验证套件证明无回归。
> 度量环境：本机（无独立 GPU），Godot 4.7.2 / GL Compatibility，`LIBGL_ALWAYS_SOFTWARE=1`（llvmpipe 软渲染）。

## 1. 审计结论（按优先级）

| 级别 | 发现 | 影响 |
|---|---|---|
| **P0** | `main.tscn` 根节点额外挂了 `game_manager.gd`（与 autoload 重复）。`game_manager._ready()` 会把 `process_mode` 设为 `PROCESS_MODE_ALWAYS` 且作用于**自身**，基线里根节点变成 ALWAYS → **所有子节点继承** → `get_tree().paused` 名存实亡，暂停不冻结任何玩法节点；同时同一状态被两个实例读写 | 正确性缺陷（暂停/存档双写者），且掩盖了 HUD 对继承 ALWAYS 的隐式依赖 |
| **P1** | 昼夜循环只对**第一个** `street_generator` 下发夜光，其余两个街区夜里灯不亮（0/33、0/30） | 核心"昼夜→灯光"效果残缺 |
| **P1** | 阴影通道开销占比过高：太阳阴影 + 立面微细节全部进 shadow pass | 两机位 1725~2183 draw calls |
| **P2** | 脚本热路径：`day_night_cycle._process` 每帧读系统时间/写光照属性；`ambience_controller` 每帧解析玩家与音量比较；`npc_base` 名牌淡入淡出每帧写 `modulate`；`hud_hints` 每帧重写交叉准星/提示文本 | 无谓的每帧属性写与信号查找 |
| **P2** | 设置写放大：滑杆 `value_changed` 每个事件都写盘，且写盘非原子 | 拖动滑杆时高频 `user://` 写，中断会截断存档 |
| **P3** | 距离细节剔除 / 网格合并 / MultiMesh | 收益大但与 `street_check` 的"直接子节点名"断言冲突，列为 V2 |

## 2. 设计原则（本次遵循）

1. **先诊断再优化**：每条优化都必须有"同机位/同路线"的前后度量，没有度量就不进主干。
2. **质量优先于收益**：任何可能改变观感的开关，都要用可复现的 A/B 证明等价；证明不了就回滚或降级。
3. **回归即证据**：优化必须配套"锁行为"的断言，防止后续迭代把效果改没。
4. **诚实标注边界**：llvmpipe 只做相对对比、headless 只测逻辑帧、截图只做无缺件抽查。

## 3. P0：状态唯一写者与暂停语义

### 根因
`main.tscn` 根节点 `Main` 上挂了 `ExtResource("1_gm")`（`game_manager.gd`），与 autoload `GameManager` 重复。`_ready()` 内的 `process_mode = Node.PROCESS_MODE_ALWAYS` 因此作用到根节点，整棵玩法树被抬成 ALWAYS。

### 改动
- `godot-project/scenes/main.tscn`：删除根节点脚本引用（状态写者唯一 = autoload）。
- `godot-project/scripts/ui/hud_hints.gd`：根因修复后 HUD 不再继承 ALWAYS，暂停时准星/提示会"冻住不清除" → `_ready()` 显式声明 `PROCESS_MODE_ALWAYS` 并注释整条继承链；`_refresh_hint_text()` 增加 `_current_npc == null / not is_instance_valid` 守卫（修复 `Cannot call method 'has_method' on a null value`）。
- `godot-project/scripts/debug/dialog_check.gd`：新增 **§0 回归锁** ——
  - 根节点下挂 `scripts/autoload/game_manager.gd` 脚本的节点数必须 `== 1`；
  - `Main` 根节点必须无脚本（"状态唯一写者=autoload"）。

### 语义决策（已落地并写入断言）
只有 `game_manager`（autoload）、`hud_hints`、`settings_panel` 声明 `PROCESS_MODE_ALWAYS`；Player / NPC / 环境音 / 昼夜循环在暂停时**真正冻结**（这是预期行为），恢复后昼夜按系统时间自然追平。

## 4. 渲染优化（阴影通道）

### 4.1 采纳：阴影距离裁剪
`main.tscn` Sun 节点新增 `directional_shadow_max_distance = 45.0`。

| 距离 | draw calls 归因（`shadow_diag` 同机位） |
|---|---|
| 45 m | **−420** |
| 60 m | −257 |
| 80 m | −132 |
| 默认 100 m | 基线 |

45 m 在街景第一人称视距内（主街长 494 m，但玩家关注 <45 m），实测静态机位视觉差异 ≤2.2。

### 4.2 采纳：立面微细节不进阴影通道
`street_generator.gd::_dmesh()` 设 `mi.cast_shadow = SHADOW_CASTING_SETTING_OFF`，**−287 draw calls**。
檐口/门斗/落水管/烟囱压顶等投影是 ≤0.5 m 贴面细线；几何、材质、拾取、`street_check` 的节点名断言均不受影响。

### 4.3 归因分解（`shadow_diag` / `detail_lod_diag`，同机位）

| 手段 | draw calls Δ |
|---|---|
| 关闭太阳阴影（仅诊断，未采纳） | −920 |
| 隐藏立面细节（仅诊断，未采纳） | −413 |
| 隐藏街道道具（仅诊断，未采纳） | −186 |
| `max_distance=45`（**采纳**） | −420 |
| 立面微细节不投影（**采纳**） | −287 |
| 二者组合（**实际落地**） | **1752 → 1067（−685）** |
| 距离细节剔除 25/40/60 m（**未采纳，V2**） | −377 / −246 / −180 |

## 5. 取证方法学修正（本轮最重要的一课）

优化过程中截图 A/B 曾给出**三个假阳性结论**，全部由取证工具缺陷造成，已修正工具并作废原结论：

| # | 缺陷 | 造成的假象 | 修正 |
|---|---|---|---|
| 1 | 截图只在机位摆好后等 **2 帧** | 抓在过渡段（`_shadow_probe` 实测第 6~14 帧路面亮度 33~45 波动，**第 15 帧起恒定 43.56**） | 改为固定等 **16 帧**收敛，期间每 4 帧重藏设置面板 |
| 2 | 失焦自动暂停在两侧**状态不一致**（基线因全树 ALWAYS 实际不冻结，修复后会真冻结） | 一侧世界被冻结（玩家不落地、NPC 不推进）→ 同机位假差异 **~40** | 取证期间**每帧强制 `paused = false`** |
| 3 | `git stash` 回滚基线时**连截图脚本一起回滚** | 两侧用了不同等待帧数 → 假差异 9~27 | **选择性 stash**：只回滚被优化的游戏文件（`main.tscn` + 5 个玩法脚本），保留取证脚本 |

修正后重新测量的等价性矩阵（mean_abs_diff，0~255，`LV_FIXED_HOUR=15.0`）：

| 对比 | `01_player_view` | `04_cafe_front` | `05_street_end` | `09_arcade_wide` |
|---|---|---|---|---|
| 纯代码改动 vs 基线 | 0.0 | 0.0 | 0.0 | 0.4 |
| + `max_distance=45` vs 基线 | 0.6 | 0.3 | 0.2 | 2.2 |
| + 立面细节不投影 vs 基线 | 0.6 | 0.4 | 0.3 | 2.4 |
| 同一配置跑两次 | 0.0 | 0.0 | 0.0 | 0.0~0.6 |
| 路面亮度（`05` 采样区） | 基线 / 最终均 `rgb=(40.5,43.6,55.7)` | | | |

`08_arcade_close` 差异 23~32 属 **NPC 走位**：同一配置两次运行之间就有 27.8~31.8 的差异，两侧均存在，与优化无关（该机位本就是"运行中世界"的 NPC 取证位）。

> 作废的旧结论（记录以免重犯）："立面细节不投影导致路面 −17%"、"阴影整体翻转"、"max45 引入阴影闪烁/条纹（acne）" —— 全部来自上表 1~3 号方法缺陷；修正后路面亮度逐值相同、同配置两次运行 0.0~0.6。


## 9. V2 待办（明确不做及原因）

| 项 | 预期收益 | 不做的原因 |
|---|---|---|
| 距离细节剔除 25/40/60 m | −377 / −246 / −180 draw calls | 需改 `street_check` "直接子节点名"断言策略（`Wall/Facade/Detail_*` 必须仍在直接子级） |
| 网格合并 / MultiMesh | 大幅合批 | 同上，且会破坏按节点名的面数预算断言（决策 29） |
| 阴影 bias 显式化 + 等价性断言锁 | 把"视觉等价"从人工取证变成自动断言 | 目前等价性靠截图矩阵人工核对；需先设计可 headless 化的像素/亮度断言 |
| 街区生成异步化 | 消掉 `add_child` 184 ms + 首帧 133/50 ms | 属加载体验优化，需引入分帧生成与进度反馈，风险面大于本轮目标 |
| 开启性能阈值强制 | `thresholds_enforced=true` | 依赖真机基线；当前仅 llvmpipe 相对对比，强设阈值即撒谎 |
| 设置写盘 debounce | 已由"拖动结束才 flush"解决大头 | 剩余场景（键盘调节）频率极低 |

## 10. 诚实边界

- **llvmpipe 软渲染仅作相对对比，不声称真机帧率**；`perf` 报告 `scope` 明写"仅逻辑/物理帧耗时，不含 GPU 渲染与窗口合成"。
- 截图对比只用于"**无缺件、无材质丢失、亮度等价**"抽查，**不声称画面好看**、不做法语/美术质量评价。
- 断言计数为单次运行的行计数，随断言增删变化；README/PRODUCT 中的数字已同步为本次实测值。
- 启动期 184 ms + 133/50 ms 已定位为世界构建与首次同步，**不是**渲染优化可消除的项。
