## 〇、锁定的技术路线

```
① OSM 真实数据 (Overpass API) — 已拉取 ✅
        │  Python 预处理脚本 (tools/)
        ▼
② 布局 JSON（建筑中心点/尺寸/层数/朝向 + 咖啡馆锚点）
        │  Godot 加载
        ▼
③ Godot 程序化生成器 (GDScript)
        │  盒子建筑 + Haussmann 配色 + Shader 窗户
        ▼
④ 主场景 = 街景骨架 + 实例化"咖啡馆"
        ▲
        │ Blender 手搭咖啡馆 .glb（招牌/露台/柜台）
```

## 四、坐标系统

```
OSM 经纬度 (lat/lon)
    │  等距圆柱投影：x = (lon - lon0) × 73,000 m/°（cos48.8° × 111,000）
    │                  z = (lat0 - lat) × 111,000 m/°（向北为 -z，向地图下方为 +z 或按需翻转）
    ▼
Godot 世界坐标 (x, z) — 街道沿 Z 轴延伸，建筑两侧分布
    │  旋转整街使主街方向对齐 Z 轴（-64° 补偿）
    ▼
玩家出生点：街道一端，朝向咖啡馆
```

## 五、验收标准（对照 V1 完成标准）

1. 主场景加载即见真实布局的玫瑰街（非对称盒子排列）
2. 街侧建筑 6 层 Haussmann 观感（奶白墙 + 灰顶 + Shader 窗户）
3. 咖啡馆 .glb 可进入，柜台后 Marie 可对话
4. 玩家可在整条街行走（碰撞体完整，无穿模）
5. 性能：< 30k 面，桌面 60 fps

## 六、风险与缓解

| 风险 | 概率 | 缓解 |
|------|------|------|
| OSM footprint 有噪点/重叠 | 中 | 预处理简化：凹多边形 → 外接盒 + 合并近邻 |
| Shader 窗户在 GL Compatibility 渲染器受限 | 低 | 用基础 canvas/spatial shader 特性；退化纯色 |
| Blender 咖啡馆模型过大 | 低 | 限 10-20k 面，家具实例化复用 |
| 单栋建筑过多导致 draw call 高 | 低 | MultiMesh 实例化同尺寸楼；面数远低于预算 |

## 八、无头渲染验证方法（沙箱/CI 用）

沙箱无 GPU 时用 llvmpipe 软件渲染截图:

```bash
# 首次须设可写 XDG_DATA_HOME(否则 EGL shader cache 创建失败 → 全图灰)
mkdir -p .userdata
XDG_DATA_HOME=$PWD/.userdata LIBGL_ALWAYS_SOFTWARE=1 \
  ./tools/Godot_v4.7.2-stable_linux.x86_64 --rendering-driver opengl3 \
  --path godot-project -s res://scripts/debug/screenshot_capture.gd
# 输出: godot-project/screenshots/shot_01..05_*.png
```

**坑：** 沙箱 llvmpipe 下 `user://` 不可写会导致 shader 编译失败、画面全灰且 0 饱和度——先设 XDG_DATA_HOME 再诊断颜色。真实 GPU（NVIDIA）用户直接:

```bash
./tools/Godot_v4.7.2-stable_linux.x86_64 --path godot-project
```
按 F5 目检。截图 4 视角存档于 `godot-project/screenshots/`（已 gitignore）。
