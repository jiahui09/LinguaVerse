**关键决策：** 本机未安装 Blender。如需自建资产，需要安装 Blender 或使用在线工具。

## 三、LLM API 方案

### 3.1 主要选项

| 供应商 | 法语支持 | 流式响应 | 成本（输入/输出 per 1M tokens） | 推荐度 |
|--------|---------|---------|-------------------------------|--------|
| **DeepSeek** | ✅ 优秀 | ✅ SSE | ~$0.14 / $0.28 | ⭐⭐⭐ |
| **OpenAI (GPT-4o)** | ✅ 优秀 | ✅ SSE | ~$2.50 / $10.00 | ⭐⭐ |
| **OpenAI (GPT-4o-mini)** | ✅ 良好 | ✅ SSE | ~$0.15 / $0.60 | ⭐⭐⭐ |
| **Claude (Sonnet)** | ✅ 良好 | ✅ SSE | ~$3.00 / $15.00 | ⭐⭐ |
| **Ollama（本地）** | ⚠️ 取决于模型 | ✅ 本地 | 免费 | ⭐⭐ |

### 3.2 推荐方案

```
开发阶段 → Ollama 本地运行（零成本、快速迭代）
测试阶段 → DeepSeek API（成本低、法语好）
生产阶段 → DeepSeek / GPT-4o-mini（按需切换）
```

### 3.3 关键技术点

- **流式响应（SSE）：** 所有主流 LLM API 都支持，确保 NPC 回话"逐字出现"
- **Prompt 组装：** 后端统一封装，前端不接触 API Key
- **对话历史：** 每次请求携带最近 N 轮对话作为上下文
- **法语生成质量：** DeepSeek 和 GPT-4o 在法语生成上表现优秀

## 四、Web 端 3D 性能基准

### 4.1 参考数据

| 场景复杂度 | 典型面数 | 桌面浏览器 fps | 说明 |
|-----------|---------|---------------|------|
| 简单场景（<10k 面） | 5,000 | 60+ fps | V1 咖啡馆内部 |
| 中等场景（10k-50k 面） | 30,000 | 40-60 fps | V1 街区场景 |
| 复杂场景（50k-200k 面） | 100,000 | 20-40 fps | 需要 LOD |
| 大型场景（>200k 面） | 500,000 | <20 fps | 需要 chunk 加载 |

### 4.2 V1 性能预算

```
V1 目标：桌面浏览器 30+ fps
├── 建筑模型：5,000-15,000 面（3-5栋建筑）
├── 家具/道具：2,000-5,000 面
├── NPC 模型：1,000-3,000 面 × 3
├── 地面/天空：1,000 面
├── 总计：约 15,000-30,000 面
└── 预期 fps：40-60 fps（无 LOD 即可达标）
```

**结论：** V1 场景规模（100m 街道 + 1个咖啡馆）在 30,000 面以内，Web 端完全可以承受，不需要 LOD。

### 4.3 优化策略（V1 备用）

| 策略 | 说明 | V1 是否需要 |
|------|------|------------|
| 视锥剔除 | Three.js 自动支持 | ✅ 自动 |
| 实例化渲染 | 相同模型复用几何体 | ❌ V1 模型少 |
| LOD | 远距离低精度 | ❌ V1 场景小 |
| 纹理压缩 | KTX2 格式 | ⚠️ 可选 |

## 八、关键风险与建议

### 8.1 技术风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| Web 3D 性能不足 | 低 | 高 | V1 场景足够小，不需要复杂优化 |
| LLM 响应延迟 | 中 | 中 | NPC 思考动作 + 流式响应 |
| 3D 资产质量不足 | 中 | 中 | 混合来源 + Blender 简单调整 |
| 浏览器兼容性 | 低 | 中 | 只支持现代浏览器（Chrome/Firefox/Edge） |

### 8.2 建议

1. **先跑通文本对话闭环**——用 Ollama + 简单 TUI，验证 AI 对话体验
2. **再搭 3D 场景**——用 CC0 资产快速搭建，不追求完美
3. **最后串联**——把对话系统接入 3D 场景
4. **Blender 按需安装**——如果 CC0 资产不够用再装
