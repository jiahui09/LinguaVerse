# 巴黎数字孪生技术方案

**目标：** 基于真实巴黎数据生成3D场景，让玩家沉浸式体验巴黎街景
**日期：** 2026-09-06
**状态：** 技术调研

---

## 〇、核心思路

> **不用手动建模每栋楼——用真实地图数据自动生成3D巴黎。**

```
OpenStreetMap（巴黎街道+建筑数据）
        │
        ▼
  Blender（OSM → 3D 网格）
        │
        ▼
  巴黎风格材质（Haussmann 建筑外立面）
        │
        ▼
  Godot（运行时渲染 + 交互）
```

---

## 一、数据源

### 1.1 OpenStreetMap（OSM）— 核心数据

| 数据类型 | 内容 | 精度 |
|---------|------|------|
| 街道 | 巴黎每条街的精确形状、宽度、名称 | 非常高 |
| 建筑轮廓 | 每栋楼的 footprint（底面形状） | 高 |
| 建筑高度 | 部分建筑有 `height` 标签 | 中（约60%覆盖） |
| 建筑层数 | `building:levels` 标签 | 中 |
| 地标 | 凯旋门、埃菲尔铁塔等 | 高 |
| POI | 咖啡馆、餐厅、商店位置 | 高 |
| 街道名称 | 每条街的真实名称 | 100% |

**获取方式：** Overpass API（免费，无需注册）

```
# 查询巴黎某个区域的所有建筑
[out:json];
area["name"="Paris"]["admin_level"="8"]->.searchArea;
(
  way["building"](area.searchArea);
);
out body;
>;
out skel qt;
```

### 1.2 Mapbox 3D Buildings — 补充数据

| 特性 | 说明 |
|------|------|
| 3D 建筑模型 | 带高度的建筑体积 |
| API 免费额度 | 每月 10 万次请求免费 |
| 格式 | GeoJSON /矢量瓦片 |

**用途：** OSM 缺少高度数据的建筑，用 Mapbox 补充。

### 1.3 Google Street View — 视觉参考

| 用途 | 说明 |
|------|------|
| 建筑外立面参考 | Haussmann 风格的颜色、纹理、阳台 |
| 街道氛围参考 | 路灯样式、行道树种类、路面材质 |
| 咖啡馆内部参考 | 法国咖啡馆的典型布局 |

## 二、技术路径

### 路径 A：Blender + OSM 插件（推荐）

```
1. 安装 Blender GIS 插件（免费开源）
2. 在 Blender 中导入巴黎 OSM 数据
3. 自动根据建筑轮廓 + 高度生成3D体积
4. 应用巴黎风格材质
5. 导出 glTF → Godot 导入
```

**Blender GIS 插件：**
- GitHub: https://github.com/domlysz/BlenderGIS
- 功能：直接在 Blender 中加载 OSM 数据，自动生成3D地形和建筑
- 状态：活跃维护

**优点：**
- ✅ 免费开源
- ✅ 直接在 Blender 中操作，可视化编辑
- ✅ 可以手动调整每栋建筑
- ✅ 导出 glTF 直接给 Godot

**缺点：**
- ⚠️ 大量建筑时 Blender 可能卡顿
- ⚠️ 需要手动应用材质

### 路径 B：Python 脚本自动生成

```
1. 用 Python + osmium 库解析 OSM 数据
2. 提取建筑轮廓 + 高度
3. 用 trimesh / shapely 生成3D网格
4. 批量导出 glTF
5. 导入 Godot
```

**优点：**
- ✅ 完全自动化，可批量处理
- ✅ 可以精确控制生成逻辑
- ✅ 适合生成整个街区

**缺点：**
- ⚠️ 需要编写脚本
- ⚠️ 没有可视化界面

### 路径 C：Cesium + 3D Tiles（重量级）

```
1. 用 Cesium OSM Buildings（免费3D建筑数据集）
2. 导出为 3D Tiles 格式
3. 在 Godot 中加载 3D Tiles
```

**优点：**
- ✅ 数据最完整（全球建筑都有）
- ✅ 带真实高度和纹理

**缺点：**
- ❌ Godot 不原生支持 3D Tiles
- ❌ 需要额外转换工具
- ❌ 数据量大，Web 端性能压力大

## 三、巴黎 Haussmann 建筑特征

巴黎最标志性的视觉是 **Haussmann 建筑**——19 世纪奥斯曼男爵改造巴黎时统一规划的建筑风格。

### 3.1 建筑参数

| 参数 | 数值 | 说明 |
|------|------|------|
| 层数 | 6-7 层 | 底层商铺 + 中间住宅 + 顶层阁楼 |
| 高度 | 18-25 米 | 含屋顶 |
| 外墙材质 | 奶白色石灰岩 | 巴黎特有的 Lutetian 石灰岩 |
| 屋顶 | 深灰色锌板 | 巴黎标志性的灰色斜屋顶 |
| 阳台 | 铸铁栏杆 | 2-6 层有连续阳台 |
| 窗户 | 竖长方形 | 百叶窗，对称排列 |
| 底层 | 商铺 | 咖啡馆、面包店、书店 |

### 3.2 材质方案（低多边形风格）

```
建筑外墙 → 奶白色（#F5F0E8）纯色
屋顶     → 深灰色（#4A4A4A）纯色
窗户     → 深蓝色（#2C3E50）纯色
阳台栏杆 → 深灰色（#333333）线条
底层商铺 → 深绿色（#2D5A27）门框 + 橱窗
```

### 3.3 巴黎街道元素

| 元素 | 样式 | OSM 数据 |
|------|------|---------|
| 路面 | 石板路 / 沥青 | ✅ 有道路数据 |
| 行道树 | 梧桐树（巴黎最常见的行道树） | ⚠️ 部分有 |
| 路灯 | 黑色铸铁复古路灯 | ❌ 需手动添加 |
| 长椅 | 绿色金属长椅 | ❌ 需手动添加 |
| 地铁入口 | Art Nouveau 风格 | ⚠️ 部分有 |

## 四、具体实现方案（推荐路径 A）

### 4.1 选定区域

**推荐：巴黎玛黑区（Le Marais）3区-4区**

| 特征 | 说明 |
|------|------|
| 位置 | 巴黎市中心，塞纳河右岸 |
| 面积 | 约 1km²（足够大） |
| 建筑风格 | 典型 Haussmann 建筑，保存完好 |
| 街道 | 窄街小巷，适合步行探索 |
| 咖啡馆密度 | 非常高，符合游戏场景 |
| 知识产权 | 公共区域，无限制 |

**具体范围：** 从 Place des Vosges（孚日广场）到 Rue de Rivoli，约 500m × 500m。

### 4.2 工作流程

```
Step 1: 下载 OSM 数据
        → Overpass API 查询玛黑区建筑
        → 保存为 .osm 文件

Step 2: Blender 导入
        → 安装 Blender GIS 插件
        → 导入 .osm 文件
        → 自动生成3D建筑体积

Step 3: 材质应用
        → 批量设置 Haussmann 风格材质
        → 奶白外墙 + 灰色屋顶

Step 4: 细节添加
        → 手动添加路灯、长椅、行道树
        → 标记可进入的咖啡馆

Step 5: 导出
        → 导出为 glTF 格式
        → 导入 Godot

Step 6: 交互设置
        → 在 Godot 中设置 NPC 点位
        → 设置碰撞体
        → 设置对话触发区域
```

### 4.3 面数预算

| 元素 | 预估面数 | 说明 |
|------|---------|------|
| 建筑（50-100栋） | 30,000-60,000 | 每栋 300-600 面（盒子简化） |
| 街道路面 | 2,000-5,000 | 平面 + 纹理 |
| 行道树 ×20 | 10,000-20,000 | 低多边形树 |
| 路灯 ×15 | 3,000-5,000 | 简单几何体 |
| 长椅 ×10 | 2,000-3,000 | 简单几何体 |
| **总计** | **50,000-90,000** | **Web 端可接受** |

## 五、Godot 中的实现

### 5.1 场景结构

```
Paris_Marais（主场景）
├── Terrain（地面）
├── Buildings（建筑群）
│   ├── Building_001（每栋建筑是独立节点）
│   ├── Building_002
│   └── ...
├── Streets（街道）
├── Props（道具：路灯、长椅、树）
├── NPCs（NPC 点位）
├── Player（玩家）
├── Lighting（光照）
└── Audio（环境音）
```

### 5.2 LOD 策略（V1 简化）

V1 场景规模不大（500m × 500m），不需要复杂 LOD：
- 近距离：完整模型
- 远距离：简化盒子（Godot 自动视锥剔除）

### 5.3 碰撞体

- 建筑：用简化盒子碰撞体（不需要精确网格碰撞）
- 地面：平面碰撞体
- 道具：简化碰撞体

## 六、替代方案：如果 OSM 数据不够用

| 问题 | 解决方案 |
|------|---------|
| 建筑高度数据缺失 | 用 Mapbox 3D Buildings 补充 |
| 建筑细节不足 | 用 Haussmann 风格程序化生成窗户、阳台 |
| 街道元素缺失 | 手动添加路灯、长椅等 |
| 材质不够真实 | 用 Google Street View 参考，手绘纹理 |
